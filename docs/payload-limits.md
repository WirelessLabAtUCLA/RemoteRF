# Payload Size Limits

Every RemoteRF call passes through a transport (LAN gRPC, direct QUIC, RemoteRF Global relay, or MCP), a wire codec, and a device driver. Whichever layer has the lowest limit decides how much data fits in a single call.

Paths prefixed with `remoterf-global:` below refer to files in the RemoteRF Global (federation) repository; all other paths are relative to the RemoteRF monorepo root.

## Quick summary by path

- **On the lab's LAN (gRPC):** Requests and responses can be up to **100 MiB** per gRPC message (both client↔server and server↔host tunnel). In practice, a single NumPy array is capped at **64 MiB** on legacy `GenericRPC` calls or **16 MiB** on Dynamic v2 control calls, and sample-streaming drivers cap individual sample transfers at **4 MiB** (RTL-SDR, HackRF, KrakenSDR, Dynamic v2 USRP).
- **Direct to the lab or a host over QUIC (or host TCP fallback relay):** Calls directly to a **lab server** over QUIC allow up to **100 MiB** frames in both directions. Calls directly to a **host** (over QUIC or the host's TCP fallback relay) cap incoming requests at **16 MiB**, while responses can be up to **100 MiB** (the client's frame limit). Codec caps (**64 MiB** ndarray) and driver sample caps (**4 MiB**, or **128 KiB** if a federated Dynamic v2 session opened through the bridge) still apply. Driver schema fetches never use the direct path.
- **Through RemoteRF Global:**
  - **Global account HOME (client → Global → lab):** Requests are capped at **192 KiB** (unpaged). Responses up to **768 KiB** return in one call; replies from **768 KiB to 4 MiB + 64 KiB** (4,259,840 bytes) are held by a current lab Server for 30 seconds and automatically fetched in **764 KiB** pages by the client. Driver schema fetches (`IDL:get_drivers`, `DynamicV2:GetSchema:WIRE`) are never paged and are hard-capped at **768 KiB**. Federated Dynamic v2 sessions advertise a **128 KiB** sample payload limit so TX frames fit under 192 KiB.
  - **Lab-as-HOME (lab → partner lab, server-to-server):** Requests are capped at **192 KiB** and responses are hard-capped at **768 KiB** with **no paging**.
- **Over MCP:** MCP exposes device discovery, reservations, and API documentation—not IQ sample transfers. On Remote Global (`POST /mcp`), HTTP request bodies are capped at **16 KiB** (`POST /oauth/register` at **4 KiB**), and `remoterf_device_api` / `remoterf_example_script` inherit the **768 KiB** unpaged schema limit (with docstrings truncated to 500 characters). Local `remoterf mcp` runs over stdio with no 16 KiB HTTP cap and inherits the active target's schema and account limits.

## Path 2: Direct to the Lab or a Host over QUIC (and Host TCP Fallback Relay)

Used for device-plane RPCs once ICE/QUIC hole-punching, the server's fixed UDP QUIC port, or a host's TLS-over-TCP fallback relay is established. Neither client nor server overrides `aioquic`'s default QUIC stream/connection flow-control windows (`QuicConfiguration` only sets `alpn_protocols` and `idle_timeout=600`). Driver schema fetches (`IDL:get_drivers`, `DynamicV2:GetSchema:WIRE`) never travel on a direct path (`client/src/remoterf/core/grpc_client.py:243-244`), and a host refuses `IDL:*` and `ACC:*` (`host/src/remoteRF_host/server/direct_host.py:205-206`).

## What to do if you hit a limit

- **Split captures and transmissions across multiple calls.** For example, loop `read_samples(65536)` on RTL-SDR/HackRF, reduce `sdr.rx_buffer_size` on ADALM-Pluto, or chunk USRP `recv()` / `send()` using `streamer.get_max_num_samps()`.
- **Use a direct QUIC path (or the lab's LAN) for large transfers.** Keep `REMOTERF_DIRECT=1` (the default) so device traffic bypasses the 192 KiB request / 768 KiB unpaged relay frame limits whenever UDP hole-punching or the fixed UDP port succeeds.
- **Keep `ci16` wire compression enabled for integer IQ.** `REMOTERF_RX_WIRE=i16` and `REMOTERF_TX_WIRE=i16` are enabled by default and pack integer complex samples as 4 bytes/sample (half of `complex64`, a quarter of `complex128`), fitting 2–4× more samples per frame on ADALM-Pluto and other integer-ADC SDRs.
- **Watch TX size over the Global relay.** Because Global requests are unpaged at **192 KiB**, a single `tx()` call without a direct path is limited to ~48k `ci16` samples, ~24k `complex64` samples, or ~12k `complex128` samples (minus protobuf overhead). For Dynamic v2 (USRP) over Global, keep each `send()` / `recv()` at or below **128 KiB** (16,384 `complex64` samples on 1 channel).
- **Avoid older servers' non-paged 768 KiB reply wall.** On a lab Server that predates paging, or when routing through a lab-as-HOME, keep single-call responses comfortably under 768 KiB (for example, `<= 65,536` `complex64` samples = 512 KiB).

## Known gaps

The following inconsistencies exist in the current implementation and are documented here as observed:

1. **Global HOME pages large replies, lab-as-HOME does not.** A Global account HOME automatically pages replies between 768 KiB and 4 MiB + 64 KiB via `Federation:page:CALL2` (`client/src/remoterf/core/grpc_client.py:274-285,808-831`; `server/src/remoteRF_server/server/federation/devices.py:67-69,519-564`). A lab acting as HOME (`server/src/remoteRF_server/server/federation/home_devices.py:450-471`) has no paging loop and hard-fails at 768 KiB (`Partner refused: response_too_large`), even though the destination lab holds the reply for 30 s.
2. **Global relay requests are unpaged at 192 KiB while replies page to 4 MiB + 64 KiB.** There is no request paging or chunking on the Global relay (`packages/remoterf-federation-core/src/remoterf_federation_core/devices.py:35`), making TX frames over the relay more than 20× smaller than paged RX frames.
3. **Lab direct QUIC vs. Host direct request cap asymmetry.** Lab Server direct QUIC accepts incoming frames up to 100 MiB (`packages/remoterf-device-core/src/remoterf_device_core/direct.py:32`), whereas Host direct QUIC and Host TCP fallback relay cap incoming requests at 16 MiB (`host/src/remoteRF_host/server/direct_host.py:48`). Outgoing Host responses are not checked against 16 MiB (only against the client's 100 MiB `MAX_FRAME` at `client/src/remoterf/core/direct_path.py:76`), and client `frame()` (`client/src/remoterf/core/direct_path.py:163`) performs no pre-send size check.
4. **Federated Dynamic v2 stays clamped to 128 KiB even on direct QUIC and even for RX.** `server/src/remoteRF_server/server/dynamic_v2_bridge.py:44,200-209` clamps `maximum_sample_payload_bytes` to 128 KiB in `OpenSession` so TX fits under the 192 KiB relay request cap. The client applies that single capability to both `RXStreamer.recv()` and `TXStreamer.send()` (`client/src/remoterf/drivers/dynamic_v2.py:449-456,531-538`), so RX is also clamped to 128 KiB (despite 768 KiB / 4 MiB + 64 KiB relay RX support) and the 128 KiB cap persists even when traffic uses a direct QUIC path. Meanwhile, the server's `SampleDataV1Servicer` still enforces 4 MiB (`server/src/remoteRF_server/server/dynamic_v2.py:76,1913`), not 128 KiB.
5. **Misleading `response_too_large` message when exceeding the 4 MiB + 64 KiB paging ceiling.** Replies larger than 4 MiB + 64 KiB are dropped by the destination with `response_too_large` (`server/src/remoteRF_server/server/federation/devices.py:526-529`). After `Federation:page:CALL2` fails, the client reports `"the reply is over the Global relay's 768 KiB limit for one call and this deployment does not page it"` (`client/src/remoterf/core/grpc_client.py:281-285`), which does not mention the 4 MiB + 64 KiB paging limit (and `client/src/remoterf/core/messages.py:73` similarly mentions only 768 KiB).
6. **Legacy base64 fallback admits slightly less than 192 KiB / 768 KiB.** `MAX_DEVICE_RPC_REQUEST_FRAME_BYTES` (196,608 B) base64-encodes to exactly `MAX_DEVICE_ACTION_REQUEST_BYTES` (262,144 B), and `MAX_DEVICE_RPC_RESPONSE_FRAME_BYTES` (786,432 B) base64-encodes to exactly `MAX_DEVICE_RESULT_BYTES` (1,048,576 B) (`packages/remoterf-federation-core/src/remoterf_federation_core/devices.py:28-29,35-36`). Because canonical JSON validation checks the entire JSON object including envelope metadata (`packages/remoterf-federation-core/src/remoterf_federation_core/federation.py:407`, `devices.py:674`), the legacy base64 fallback rejects frames within a few hundred bytes of 192 KiB / 768 KiB that detached binary framing accepts.
7. **RX read-ahead is clamped to 764 KiB even on LAN and direct paths, and is unimplemented on Hosts.** `client/src/remoterf/core/grpc_client.py:756` fixes `_RX_N_BYTES = 786432 - 4096` regardless of transport, and `host/src/remoteRF_host/server/rpc_manager.py` implements neither `:rx_n:CALL1` nor `:batch:CALLN` (so direct-to-host calls fall back to unbatched calls).
8. **Inconsistent ICE signaling caps across paths.** Federated `direct_open` caps ICE offers and answers at 8 KiB (`packages/remoterf-federation-core/src/remoterf_federation_core/devices.py:54`, `remoterf-global:src/remoterf_global/deployment/app.py:192`), server validation of a Host ICE answer allows 16 KiB (`server/src/remoteRF_server/server/host_direct.py:259`), and LAN `ACC:direct_offer` has no ICE cap below the 100 MiB gRPC limit.
9. **Unauthenticated fixed-port QUIC hello allows 100 MiB vs. 64 KiB on Host TCP relay.** Lab Server fixed-port QUIC `_Conn._claim` reads the pre-auth hello with `read_frame()` up to `MAX_FRAME = 100 MiB` (bounded only by `HELLO_SECONDS = 5`, `server/src/remoteRF_server/server/direct_path.py:86,353`), whereas Host TCP fallback relay caps pre-auth hellos at `MAX_RELAY_HELLO_BYTES = 64 KiB` and 16 concurrent unauthenticated sockets (`host/src/remoteRF_host/server/direct_host.py:49,53,360`).
10. **Inconsistent driver-level sample caps.** RTL-SDR, HackRF, KrakenSDR, Dynamic v2 USRP, and `ti_mmwave` enforce 4 MiB caps (and `ti_awr6843`'s parser caps UART packets at 64 KiB at `packages/remoterf-device-core/src/remoterf_device_core/drivers/ti_awr6843/mmwave/parser.py:118`), whereas legacy v1 USRP (`packages/remoterf-device-core/src/remoterf_device_core/drivers/usrp/usrp_schema.py:1133-1159`) and ADALM-Pluto / Pluto MIMO (`pluto_schema.py`, unless an admin sets `tx_max_buffer_samples`) impose no built-in driver sample cap.
11. **`map_iq16` omits the 64 MiB encode check.** `client/src/remoterf/common/utils/process_arg.py:47-56` (and `packages/remoterf-device-core/src/remoterf_device_core/utils/process_arg.py:47-56`) validates `_MAX_NDARRAY_BYTES` only on decode (`:85`), not before serializing `ci16`, so an oversized `ci16` array is sent over the wire before failing on the receiver.
12. **Unbounded client CA certificate fetch.** `client/src/remoterf/config/cert_fetcher.py:85-110` reads HTTP and raw-TCP CA bootstrap responses with no byte cap, whereas the broker caps lab CA fetches at `MAX_CA_BYTES = 64 KiB` (`remoterf-global:src/remoterf_global/api/federation.py:67`) and cluster status routes cap `ca_pem` at 16 KiB (`remoterf-global:src/remoterf_global/api/invites.py:285`).
